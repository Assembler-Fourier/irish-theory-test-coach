## Recommended PR Strategy

1. Keep PR #1 as historical portfolio-upgrade context until commercial passes are split and reviewed.
2. Use `codex/commercial-v1` as the new baseline branch for commercial hardening.
3. Merge commercial passes as small, named PRs: baseline, payments, entitlement, content QA, admin, analytics, SEO, release.
4. Keep generated local artifacts ignored; only commit source, deterministic generated public runtime files, and documentation needed for deployment.
5. Run `npm run qa` before every pass commit.
6. Do not deploy production automatically from commercial passes until the release checklist, Stripe webhook, live checkout, support email, and secret rotation are verified manually.

## Baseline Decision

The repository is suitable for continued commercial hardening on `codex/commercial-v1` after this pass because:

- Question content remains intact.
- Runtime counts and price/access text now come from generated product-summary values.
- A stale-build check now blocks drift between data, pricing, generated HTML, sitemap, and release manifest.
- Existing preview, payment, restore, admin, SEO, and PWA flows are covered by the QA command.
